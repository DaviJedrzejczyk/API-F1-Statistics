# Project Documentation Guidelines

Use this guide when writing or updating documentation for API-F1-Statistics.

## Language and style

- Write in clear, concise English.
- Use Markdown headings, lists, and fenced code blocks to make information easy to scan.
- Prefer accurate, task-oriented instructions over generic descriptions.
- Use the project's existing terminology and formatting conventions.

## Content

Document only behavior that has been verified in the current codebase. Where relevant, explain:

- The project's purpose and main features.
- Prerequisites and how to build, run, and test the application.
- Configuration options and environment variables; never include real secrets.
- API endpoints, request parameters, response formats, and useful examples.
- Data sources, assumptions, limitations, and troubleshooting steps.

Keep examples minimal and usable. Use placeholders for credentials and other private values.

## Updating documentation

- Place content in the most relevant existing documentation file.
- Update documentation whenever a code change alters documented behavior or setup.
- Check commands, links, endpoint details, and examples against the current project.
- Remove obsolete instructions rather than leaving conflicting guidance.
- Into README write in portuguese.
